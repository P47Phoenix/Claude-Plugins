# Homiletical Structure

How a passage becomes a sermon that can be preached.

## Principle

The sermon says what the text says, then shows what it means for the listener. The structure comes from the passage; it is not imposed on it.

## Choosing a Shape

| Shape | Use when | Skeleton |
|---|---|---|
| **Expository, text-following** | The passage has clear movements | One point per movement, in the text's order |
| **Problem-resolution** | The passage names a problem and answers it | Problem -> search -> provision -> pattern |
| **Narrative** | The passage is a story | Retell, pause on turns, land on the point |
| **Thematic** | Several passages serve one theme | One theme, each passage as a witness; keep each passage in its own context |
| **Comparative / echo** | A passage reads alongside another | Passage A, passage B, what each says, where they echo (label as echo) |

State why the shape fits. Offer one main shape and, if useful, one alternative.

## Elements of a Structure

1. **Title:** short, plain, true to the text
2. **Big idea:** one sentence, the point of the passage for this listener
3. **Movements (3-5):** each tied to named verses, each with a one-line summary
4. **Bridge:** how each movement moves from "then" to "now"
5. **Forward pointer / closing:** where the passage leads (the gospel, the next passage, the call)

## Rules

- Tie every movement to verses. A movement with no verses is a topic, not exposition
- Keep exposition, illustration and application distinct and labeled
- Do not build a point on a single word unless the lexicon supports the weight placed on it
- Do not preach a passage's echo as if it were its meaning
- Mark contested readings as contested; if the sermon takes a side, say which and why, and note the other reading
- Keep each movement to one idea

## Application

- Name who the application is for (husbands, a congregation, someone doubting)
- Keep application inside what the text supports. If the application goes beyond the text, say it is an application, not the text's claim
- Offer one concrete step per movement, at most

## Manuscript Format (draft task only)

When asked to write the sermon (`draft`), append **section 8, Manuscript** to the breakdown contract:

- Written for the ear: short sentences, plain words, repeated signposts ("First...", "Now, the second movement...")
- Mark scripture readings in full on first reading, with verse numbers once, then refer by phrase
- Mark pauses with `[pause]` and emphasis with *italic*, sparingly
- Give a rough spoken length (about 130 words per minute) and note it if the user stated a target
- No quotation of anything you have not verified; no invented illustrations presented as true events. Mark a made-up illustration as "Illustration (imagined)"
- Keep the manuscript within guardrails 1-12; the verification gate will check it

## Revise (revise task)

- Work from the draft the user supplies; do not rewrite what they did not ask to change
- Return changed sections only, with the reason for each change in one line
- Re-check any citation you touch
- If the user's draft contains a claim you cannot source, say so; the gate will remove or flag it
