## Hook Script Details

`check_kicad_happy.py`:
- Scans `~/.claude/plugins/cache/kicad-happy/kicad-happy/<version>/` for skill directories
- Checks both top-level and `skills/` subdirectory layouts for SKILL.md presence
- Reports available/missing count with specific missing skill names
- Reads `.hardware/config.yml` for `dependencies.kicad_happy_version` and compares
- Always exits 0 (informational, never blocks session start)
- Output format: JSON `{"message": "..."}` per Claude Code hook protocol
- Tested: 11/11 skills detected on dev machine (kicad-happy 1.2.0 installed)

`hooks.json`:
- Matches architecture Section 9.1 exactly
- SessionStart: config validation + kicad-happy availability
- PreToolUse (Skill): pipeline bypass detection
- PostToolUse (Write|Edit): KiCad file modification notification
- Note: `check_hw_config.py`, `check_pipeline_bypass.py`, and `check_kicad_file.py` are referenced but implemented in separate stories (US-503)

## Design Decisions

1. **Hook uses JSON output** (not `lib.hook_utils`): The `lib/hook_utils.py` shared library does not exist yet. Rather than create a dependency on an unimplemented module, the hook script uses direct JSON output to stdout, which is the Claude Code hook protocol. When `hook_utils` is created (likely US-503), the hook can be refactored to use it.

2. **Version directory scanning**: The hook scans for the latest version directory under the cache path. This handles version upgrades without config changes.

3. **Dual skill path check**: Skills are checked at both `<version>/<skill>/SKILL.md` and `<version>/skills/<skill>/SKILL.md` to handle different plugin directory layouts.

4. **Contract versioning**: All contracts are version 1.0 targeting kicad-happy >=1.2.x. The update procedure (Section 7) documents how to evolve contracts when kicad-happy releases new versions.
