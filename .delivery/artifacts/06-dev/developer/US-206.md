## Design Decisions

1. **5 task types (not 4):** Added `quality-metrics` task type beyond the 4 referenced in architecture. Quality metrics tracking is essential for production hardware and naturally belongs to the TestE role. The architecture mentions quality metrics in the role description.
2. **Bring-up procedure in Gate Participation:** Rather than a separate task type, the bring-up test procedure is documented in the Gate Participation section as a Stage 4 deliverable. This matches how the CompE documents certification-readiness inline.
3. **Production tier scaling:** All task types and references scale guidance by production volume tier (Hobby/Maker, Small-batch, Production) per the architecture's complexity tiers in Section 3.2.
4. **Optional kicad-happy:kicad:** Per architecture Section 5.2, TestE has optional consumption. The skill handles both available and unavailable cases.
