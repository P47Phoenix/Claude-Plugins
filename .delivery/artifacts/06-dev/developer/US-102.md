## Design Decisions

1. **Placeholder references**: Only 3 of 8 planned reference files created (pipeline-stages, quality-gates, config-schema). The remaining 5 (rework-paths, gate-framework, memory-protocol, kicad-integration, setup-wizard) are deferred to their respective stories (US-103, US-104, US-105, US-106, etc.) to avoid creating empty files that add no value.

2. **config-schema.md as placeholder-with-content**: Although marked placeholder, it includes the full field validation table from architecture Section 6.2. This provides immediate value for US-104 (Config-Driven Pipeline) without waiting for that story.

3. **AI scope disclaimer**: Added explicit user-facing disclaimer about AI limitations -- compliance outputs are pre-compliance only, human-execution stages require physical work. This follows the memory lesson about scope limitations needing explicit disclaimers.

4. **Structural guardrails**: Task blocks in SKILL.md are designed so they only make sense for spawned agents (Step 4 Agent Invocation Template). This follows the memory lesson that guardrail language is most effective when structural.

5. **File path verification**: All reference file paths cited in SKILL.md were verified to exist via Glob before citation (pipeline-stages.md, quality-gates.md, config-schema.md). The References table at the bottom lists all 8 planned references but only 3 exist currently -- the SKILL.md text says "See references/..." which will be valid once future stories create them.
