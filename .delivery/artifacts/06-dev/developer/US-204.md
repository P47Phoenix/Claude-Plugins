## Pattern Compliance

- **Follows electrical-engineer SKILL.md pattern**: Same structure (metadata, role description, model tier, stage participation, gate participation, task types, references table, kicad-happy integration, output contracts, templates, anti-patterns)
- **Three-level context loading**: Metadata in frontmatter (L1), SKILL.md body (L2), references loaded on demand (L3)
- **NFR-003 compliance**: All fab-specific rules obtained via kicad-happy skill invocation, never hardcoded. Generic fallback rules documented as degraded-mode only.
- **NFR-002 compliance**: Anti-patterns section explicitly prohibits loading references from other role skills
- **Output contract validation**: Post-invocation validation steps for kicad-happy outputs match architecture Section 5.5.2 contract format
- **Unavailability handling**: SKILL_UNAVAILABLE protocol matches architecture Section 5.5.3 pattern
- **Sensitivity classification**: BOM validation artifact marked SENSITIVE per architecture Section 9 data classification

## Design Decisions

1. **Panelization as sub-task, not separate output**: Panelization findings are included in the DFM report rather than a separate artifact, matching the architecture's artifact tree (no separate panelization artifact listed under 05-dfm-dfa/)
2. **Yield analysis spans two stages**: yield-analysis task type supports both DFM/DFA (estimation) and Pilot Run (measurement) stages, reflecting the MfgE's primary ownership of both stages
3. **Manufacturing Readiness Assessment template**: Added as a comprehensive summary template that aggregates DFM, DFA, BOM, and test point findings -- supports the gate decision and Design Review Board participation
4. **Generic fallback rules**: Included conservative fallback values in dfm-rules.md for degraded mode when kicad-happy fab skills are unavailable, with mandatory `USING_GENERIC_FALLBACK_RULES` flag
5. **Test point coverage handoff**: Explicitly documents the boundary between MfgE (coverage assessment) and Test Engineer (fixture design, test strategy) to prevent responsibility overlap
