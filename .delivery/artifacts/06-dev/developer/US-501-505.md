## US-502: PostToolUse DRC Hook (drc_check.py)

**File:** `hardware-team/hooks/drc_check.py`

**Implementation:**
- Triggered on Write/Edit PostToolUse events
- Filters to `.kicad_sch` files only (all other files silently ignored)
- 5 basic DRC rules via static analysis of KiCad S-expression format:
  - DRC-001: Unconnected power pins
  - DRC-002: Missing component values
  - DRC-003: Missing reference designators
  - DRC-004: Duplicate reference designators (counting-based, not regex)
  - DRC-005: Dangling wire ends (info severity)
- Findings reported as non-blocking warnings
- Silent on success (no output when no violations)
- Path safety validated (null byte check)

**AC Coverage:**
- [x] Triggers on .kicad_sch file modification
- [x] Violations displayed as non-blocking warnings
- [x] Silent success when no violations

**Design Decisions:**
- Static analysis only -- full DRC requires KiCad binary (which may not be on the machine)
- Lightweight checks that catch common issues without external dependencies
- DRC rules are intentionally conservative (few false positives over completeness)

## US-503: BOM Drift Detection Hook (bom_drift.py)

**File:** `hardware-team/hooks/bom_drift.py`

**Implementation:**
- Triggered on Write/Edit PostToolUse events for `.kicad_sch` files
- Locates the most recent BOM artifact in `.hardware/artifacts/`
- Extracts reference designators from schematic (S-expression parsing)
- Extracts reference designators from BOM (markdown table / text parsing)
- Computes drift: components in schematic but not in BOM (NEW), and vice versa (REMOVED)
- Reports drift as non-blocking warning with guidance to run `kicad-happy:bom`
- Silent when no BOM exists (nothing to drift against) or no drift detected
- Filters power symbols (#PWR, #FLG, #SYM) from schematic components

**AC Coverage:**
- [x] Triggers on .kicad_sch file edit when BOM artifact exists
- [x] New/changed components listed in warning
- [x] Removed components listed in warning

**Design Decisions:**
- BOM lookup searches known artifact paths then falls back to rglob for any `*bom*` file
- Reference designator parsing uses standard prefix whitelist (R, C, L, D, U, Q, J, etc.)
- Caps drift display at 20 components per category to avoid message flood

## US-504: Pipeline Security Controls (security.py)

**File:** `hardware-team/scripts/security.py`

**Implementation:**
- **Path sanitization (SEC-01):** `sanitize_path_component()` with `^[a-zA-Z0-9._-]+$` whitelist, `safe_join()` with `os.path.realpath()` canonicalization and sandbox check. Raises `ValueError` with `HW-STA-005` error code on violations.
- **YAML safe_load enforcement (SEC-03):** `safe_yaml_load()` wrapper that pre-scans for `!!python/` tags, uses `yaml.safe_load()`, falls back to minimal regex parser when PyYAML unavailable.
- **BOM data classification (SEC-02):** `classify_bom_field()` and `is_sensitive_bom_field()` with SENSITIVE/INTERNAL/PUBLIC classification. `redact_pricing()` for memory no-pricing filter with pattern detection.
- **State file semantic validation (SEC-05):** `validate_state()` checks readability, YAML frontmatter parsing, required fields, status values, and integrity hash (advisory). `compute_integrity_hash()` for SHA-256 over stages_completed and gates.
- CLI entry point for standalone validation.

**AC Coverage:**
- [x] Path sanitization with safe_join preventing traversal outside .hardware/
- [x] yaml.safe_load enforcement (blocks !!python/object tags)
- [x] BOM data classification with SENSITIVE/INTERNAL/PUBLIC levels
- [x] State file semantic validation with integrity hash

**Design Decisions:**
- Security module is standalone (no external dependencies beyond optional PyYAML)
- Pricing regex patterns cover $, EUR, GBP, JPY and common phrasing (quoted at, priced at, costs, per unit)
- Minimal YAML parser handles single-level key-value configs for degraded-mode operation
- CLI interface enables standalone testing of each security function
