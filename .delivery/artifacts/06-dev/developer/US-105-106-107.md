## Design Decisions

1. **Path key format**: Used `<source>-><target>` with lowercase names (e.g., `prototype->schematic`) for readability in state files and log messages. Consistent with the architecture's rework_history example.

2. **Memory retrieval budget**: Kept to 2-3 reads per stage to hit NFR-008 (<2s p95). Index scan is O(n) on a small file; stage file read is a single file load.

3. **Atomic write via os.replace()**: Chose `os.replace()` over `os.rename()` because it handles cross-platform behavior (on Windows, `os.rename()` fails if target exists; `os.replace()` overwrites atomically).

4. **Staleness thresholds**: 7 days and 30 days chosen to match hardware development cadences -- prototyping often has multi-day waits for PCB fabrication, but 30+ days likely means the project context has shifted.
