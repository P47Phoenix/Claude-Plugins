## Design Decisions

1. **5 task types instead of 4:** Added `certification-readiness` as a distinct task type beyond the 4 artifacts listed in the AC. This task synthesizes the other outputs into a go/no-go assessment. Architecture Section 3.1 shows "Compliance Gate" needs evidence-linked evaluation, which maps to this task type.

2. **Three-level context loading:** References are loaded on-demand per task type, not all at once. This follows the codebase convention and keeps context lean.

3. **Rework paths from architecture:** Compliance Gate failures trigger rework to Schematic (component changes, safety issues, environmental failures) or Layout (EMC layout-only changes), matching architecture Section 3.3 rework path table.

4. **Advisory participation in Stages 2, 5, 8:** CompE has advisory/supporting roles outside Stage 6 per architecture pipeline definition.

5. **EMC risk score threshold:** Set default at risk_score < 50 for gate pass. This is configurable and should be tuned per project.
