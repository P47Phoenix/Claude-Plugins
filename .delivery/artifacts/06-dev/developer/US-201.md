## Design Decisions

1. **6 task types instead of 5**: Added `make-vs-buy` as a dedicated task type (architecture Section 1.1 lists make-vs-buy.md as a reference, and the concept brief template includes a Make-vs-Buy Summary section -- warranting a standalone task type).
2. **BOM budget in hw-requirements.md**: Rather than a separate reference file, BOM budgeting patterns are Section 4 of hw-requirements.md since budgeting is tightly coupled to requirements capture. This keeps the reference count at 3 per architecture.
3. **Decision Record pattern in SKILL.md**: Embedded in the SKILL.md itself (not a separate reference) since it is a cross-cutting pattern used by multiple task types and should be available without an additional Read call.
4. **Concept Brief and Hardware PRD templates**: Both included directly in SKILL.md as output templates, matching the task description's requirement for output templates.
5. **Gate participation expanded**: Added BOM Gate (Stage 5) and Final Gate (Stage 8) participation beyond the original placeholder's Concept and Schematic stages, reflecting the architecture's pipeline stage table where HW PO is consulted at DFM/DFA and Production Release.
