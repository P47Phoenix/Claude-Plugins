WebFetch(url=https://platform.claude.com/docs/en/docs/build-with-claude/citations)
Result summary: Anthropic's production RAG citation shape. Enable via `citations: { enabled: true }` on each document block; must be uniform (all docs or none). Three document types: (1) plain-text -> sentence-chunked, emits `char_location` with 0-indexed `start_char_index` / exclusive `end_char_index`; (2) PDF -> sentence-chunked on extracted text, emits `page_location` with 1-indexed `start_page_number` / exclusive `end_page_number` (scanned/image-only PDFs are not citable); (3) custom content -> no further chunking, emits `content_block_location` with 0-indexed block indices. Every citation object carries: `type`, `cited_text` (verbatim, does NOT count toward output tokens), `document_index` (0-indexed across ALL docs in the request), `document_title`, and the type-specific range. Response model interleaves text blocks: plain text segments have no `citations`, claim-bearing segments carry one or more citation objects. Cost/feature notes: citations compose with prompt caching (cache the document blocks via `cache_control: { type: "ephemeral" }`); cited_text also does NOT count against input tokens when passed back in later turns; citations are INCOMPATIBLE with Structured Outputs (API 400 if both set) because citation interleaving conflicts with strict JSON-schema output.

WebFetch(url=https://arxiv.org/abs/2305.14627)
Result summary: ALCE benchmark (Gao et al.) — "Enabling Large Language Models to Generate Text with Citations." Evaluates cited generation on three axes: fluency, correctness, and CITATION QUALITY. Headline finding: on ELI5, even best models lack complete citation support ~50% of the time, i.e. the cited passages fail to entail the claim. The abstract does not enumerate citation granularity explicitly but the three-axis scoring frame (fluency / correctness / citation quality) is now the de-facto ALCE rubric that later 2025 surveys reuse.
