# ADR-lmr-005: Dispatch-manifest shape (OQ-4) and the ship gate

- **Status**: Proposed (flips to Accepted when Stage 4 DoD passes)
- **Date**: 2026-09-20
- **Run**: run-2026-05-28-o48m, BACKLOG-108
- **Owner**: Solution Architect (PRD FR-7.3, FR-7.4, AC-DISP, OQ-4; BINDING-5.1, BINDING-5.4; Architect DoD round-2 F5, F8; QA W5)

## Context

AC-DISP (PRD FR-7.4) enforces "One Role = One Sub-Agent" with one file per stage, `<stage>/dispatch-manifest.txt`: line 1 `expected_validators: N`, then `<role><TAB><agent-id>` per dispatch; N must equal the line count, roles distinct, agent ids distinct. Its `REQUIRED` stage list is the PRD's guess (`02-refine`, `04-architect`, `05-plan`, `06-development`) and the PRD invites the Architect to correct it (OQ-4). The PRD also asks where the `dod_validators` counts live.

Evidence gathered in this stage (commands and files read):
- `.delivery/config.yml` lines 56 to 63 hold the source of truth: `idea: [po, architect]`, `refine: [po, architect, developer, qa]`, `design: [ux, po, qa, developer, architect]`, `architect: [architect, qa, developer, devops, security]`, `plan: [sm, po, qa, developer, devops]`, `development: [developer, qa, architect, tech-writer]`, `uat: [qa, devops, po, tech-writer]`.
- `.delivery/state.md`: `stages_completed: [1, 2]`, `stages_skipped: [3]`, routing `idea: light, refine: light, design: skip, architect: light, plan: light, development: full, uat: full`.
- `delivery-flow/SKILL.md` (Depth Definitions, read): Light = "Primary agent only, blocking criteria only, reduced DoD (primary + 1 reviewer)". Yet Stage 2 in this run, routed light, ran four validators (`.delivery/artifacts/02-refine/dod/` holds po, architect, developer, qa reviews). So N for a light stage is "validators actually dispatched", bounded by the config list, not equal to it.
- Stage directory names: `delivery-flow/references/pipeline-stages.md` line 550 writes to `artifacts/06-dev`; this run's PRD ACs and `.delivery/artifacts/` use `06-development`; both directories exist, and `06-development/dod/` already holds files from earlier waves (`S1-S2-architect-review.md`, `S3-architect-review.md`, and others). Stage 7 uses `07-uat`.
- DoD rounds and per-story units: `02-refine/dod/` and `04-architect/dod/` hold `-r2` files (a role re-validates in a second round); `06-development/dod/` holds per-story groups (`S1-S2-*`, `S3-*`). The PRD format (roles distinct within one manifest) cannot describe a second round by the same role, nor seven stories.

## Decision

1. **REQUIRED stage directories** for AC-DISP in this run: `02-refine`, `04-architect`, `05-plan`, `06-development`, `07-uat`. Excluded with reason: `01-idea` (predates the manifest rule, PRD), `03-design` (skipped, `stages_skipped: [3]`). `07-uat` is added because UAT is routed `full`, has its own `dod_validators.uat`, and (per architecture.md section 5) ship happens after UAT passes. If the Plan stage instead ships before UAT, drop `07-uat` from the list and say so in the plan; the checker takes the list as data.
2. **Stage-to-config-key map**: `02-refine` to `refine`, `04-architect` to `architect`, `05-plan` to `plan`, `06-development` to `development`, `07-uat` to `uat`. The checker reads the list with a stdlib regex on `.delivery/config.yml` lines of the form `  <key>: [a, b, c]` (no YAML dependency, per BC-03).
3. **The development directory is `06-development` for this run.** The PRD ACs (AC-3.1 ledger, AC-4.4 `s5-separation.txt`, `smoke-streams/`) already hard-code it. The orchestrator's default of `06-dev` (pipeline-stages.md) is a reference-doc mismatch to log for a later wave; the Stage 6 dispatch prompts must state `06-development` explicitly. Stale earlier-wave files in `06-development/dod/` are not read by the checker (it reads only `dispatch-manifest*.txt`).
4. **Manifest = one DoD round of one unit.** File naming: the stage-level round is `dispatch-manifest.txt`; extra rounds and per-story units are `dispatch-manifest-<label>.txt` (`-r2`, `-S1`, `-S2`, and so on). The format inside stays exactly as the PRD wrote it.
5. **Checker rules** (extends the PRD script, same negative self-test approach): for each required stage the checker requires at least one `dispatch-manifest*.txt` (a stage with none is a violation, so absence cannot pass, as in the PRD); for `06-development` it requires one manifest per story S1 to S7 (`dispatch-manifest-S<k>.txt`; a story's producer dispatches are not validators and are not listed); each manifest passes the PRD's four checks (line 1 shape, `N == lines`, roles distinct, agent ids distinct) plus two more: every role is in the config list for that stage and `N <=` the list length (BINDING-5.4: never more dispatches than the list); and every agent id is unique across ALL manifests of the run (a reused agent across rounds is a fusion or a copy).
6. **Cross-check for authorship claims (QA W5)**: the AC-4.4 `Dispatch-Id` trailers in the S5 commits must each appear in the `06-development` manifest set (producer ids under a developer role in the S5 producer manifest, the validator id under the qa role), and `run_smoke.py` joins `lib/` in the producer path list so one commit cannot touch it together with the validator files. These are additions for the Plan stage to write as AC text. **Agent ids are copied, not typed (F9).** The `<agent-id>` column and every `Dispatch-Id` value are the id string from the Agent tool result, pasted verbatim. Independent artifact: Claude Code writes one transcript per subagent under the session directory, observed here at `~/.claude/projects/<project-slug>/<session-id>/subagents/agent-<id>.jsonl` (with a `.meta.json`), e.g. `agent-a224da00ed12ff520.jsonl` (listed by `ls` this stage). The S7 checker may assert that a transcript file exists for each manifest id in the current session; that path layout is observed on this CLI only (UNVERIFIED for other versions), so it is a supporting check, not a requirement, and it is skipped with a printed note when the directory is absent. Even so, the orchestrator writes the manifests, so this remains an accepted limit (ADR-lmr-004 section 6).
7. **Base ref for pre-ship ACs** (Architect F8): the S1 developer records `base_sha=$(git merge-base main HEAD)` once, in `.delivery/artifacts/06-development/base-sha.txt`. AC-2.1, AC-2.5, AC-4.4 and AC-5.9b, which use the moving `main` ref, are evaluated against that SHA. If `main` has not advanced the result is identical; if it has, the line numbers named in AC-2.1 and the diff in AC-2.5 stay meaningful. The named source lines in AC-2.1 are properties of the base commit, not of whatever `main` is at ship time.
8. **Ship gate** (S7; revision 1 rewrites this item for adversarial findings F2 and F3). The gate runs in the checkout whose HEAD will be pushed, after the FINAL commit (CHANGELOG, memory topic, every rework edit) and after the squash-rebase and ff-merge, immediately before `git push`. The path stays squash-rebase, ff-merge, push, with no PR. Steps, in order; any non-zero exit stops the ship:
   0. Pre-ship-only ACs (AC-2.1, AC-2.5, AC-4.4, AC-5.9b), evaluated against `base-sha.txt` (item 7).
   1. `git fetch origin main`, then `git rev-list --count HEAD..origin/main` prints `0` (not behind). If not, rebase and restart at step 0.
   2. **Clean tree (F2).** `test -z "$(git status --porcelain --untracked-files=all)"` succeeds, and `git ls-files -v | grep -c '^[a-zS]'` prints `0` (no assume-unchanged or skip-worktree flags that would hide edits). With both true, the guard scope (`git ls-files --cached --others --exclude-standard`) equals the HEAD tree and file bytes equal the committed bytes, so a scan of the working tree IS a scan of the commit that is pushed. Before this fix, an unstaged edit or an untracked file could make the scan and the push disagree. Run for real in this stage: on the design worktree the porcelain check printed `?? .delivery/artifacts/04-architect/challenger/loop-1.md` (dirty, would stop the ship), and `git ls-files -v | grep -c '^[a-zS]'` printed `0`.
   3. `SHIP_SHA=$(git rev-parse HEAD)`, recorded in the log.
   4. `python3 scripts/check_model_pins.py` strict: `guard-scope hits 0 files 0`, `exit=0`.
   5. The canonical count equals the script's `--list` line count (R12 equivalence).
   6. `python3 scripts/check_skill_budgets.py` exit 0. This step is the only line-budget control on the ship path unless the push trigger below is adopted (F3): `skill-line-budget.yml` is `on: pull_request` only (`sed -n 1,8p` prints `pull_request:` and the two `paths:`), so a direct push never runs it.
   7. AC-6.1 prints `MATCH` (ADR-lmr-001), plus the telemetry-hash record required by ADR-lmr-001 decision 7.
   8. AC-DISP.
   9. `git push origin main`; then `git rev-list --count origin/main..HEAD` prints `0`.
   **Objective evidence (F3).** Steps 2 to 8 run as ONE shell block under `set -o pipefail`, teed to a log OUTSIDE the repository (`${TMPDIR:-/tmp}/ship-gate-<first 12 of SHIP_SHA>.log`; a log inside the tree would dirty it and invalidate step 2). Each step prints `step=<n> exit=<rc>` from the shell, and the block prints `SHIP_GATE=PASS sha=<SHIP_SHA>` only when every exit was 0. The S7 report cites the log path and its `sha256sum` and pastes it verbatim; a hand-typed summary is not accepted. The same executor still authors it, so the log is necessary but not sufficient; the independent check below is what makes it objective.
   **Independent post-push verification, S7b (F3).** After the push, a DIFFERENT dispatch (role `devops`, which is in `dod_validators.uat`; agent id copied from the Agent tool result, see item 6) creates a fresh clone of `origin/main` (`git clone --no-hardlinks <origin> <tmpdir>`), asserts `git rev-parse HEAD` equals the `SHIP_SHA` in the S7 log, and re-runs steps 4, 5, 6 and 7 there, returning the raw output. Its one-line manifest is `07-uat/dispatch-manifest-S7b.txt` (item 4 naming; the roles-distinct and ids-unique rules of item 5 still hold). Its report is written to `.delivery/artifacts/07-uat/ship-verification.txt` and lands in the normal post-ship state commit (docs only; `.delivery/` is outside the guard scope and no SKILL.md is touched). Procedure proven in this stage on a clone of the design worktree HEAD (`85db40f`): the clone's `git status --porcelain` printed 0 lines, the untracked challenger file was absent (a clone holds only committed bytes), `check_skill_budgets.py` printed `BUDGET CHECK PASSED: 17 file(s) checked, 0 known-debt, 0 exception(s).`, and the hash check printed `MATCH`. If S7b fails, the remedy is a fix-forward commit that goes through the whole gate again; main is never force-pushed or rewritten (irreversible; needs an explicit user decision).
   **Pre-push hook (F3, now designed into S1, not left to PO confirmation).** ADR-lmr-002 D8 specifies `.githooks/pre-push`, which for a push to `refs/heads/main` requires the pushed sha to equal `HEAD`, a clean tree, and strict runs of the guard and the budget checker. It is opt-in via `core.hooksPath` and `git push --no-verify` skips it, so it is defence in depth; the S7b check is what does not rely on the pusher.
   **Budget push trigger (PRD addition, PO confirms at Plan).** Add `push: branches: [main]` with the existing `paths:` filter to `.github/workflows/skill-line-budget.yml` (edit through `plugin-dev:hook-development`, FR-1.4 route). Verified: the checker reads `PR_BODY` with a default of empty (`os.environ.get("PR_BODY", "")`) and `env -u PR_BODY python3 scripts/check_skill_budgets.py` printed `BUDGET CHECK PASSED: 17 file(s) ...` (exit 0), so the job runs on push; it also means no `Budget-Exception:` can be granted on a push (that token lives in the PR body), which is correct for a direct push and irrelevant here (0 exceptions needed). The existing `env:` use of `github.event.pull_request.body` is not inside `run:`, so `workflow-injection-lint.yml` stays green. If the PO declines: line budgets are NOT enforced by CI on direct pushes to main, and steps 6 and S7b are the only controls; state that in the plan.
9. **SKILL.md edits after the baseline capture** invalidate what the baseline measured (Architect F8). By design the live capture is the LAST step before ship (architecture.md section 5), so no such edit is expected; if DoD rework touches a SKILL.md after the capture, either re-capture or record an explicit waiver in the S7 report.

## Alternatives rejected

| Alternative | Why rejected |
|---|---|
| Keep one manifest per stage (PRD as written) | Cannot describe a second DoD round or seven per-story units: roles repeat, so a correct run would fail AC-DISP (evidence: `-r2` files and `S1-S2-*` files above). |
| Allow repeated roles inside one manifest | Removes the very check (roles distinct) that detects a fused or duplicated dispatch. |
| Derive expected N from the config list only | Light stages legitimately dispatch fewer than the list (SKILL.md Light definition), and Stage 2 dispatched exactly the list; an equality rule would fail one of them. The bound is `N <= len(list)` and roles subset of the list. |
| Read `06-dev` per pipeline-stages.md | The PRD ACs and existing artifacts already use `06-development`; switching means rewriting AC paths. Logged as a reference-doc defect instead. |
| Parse config with PyYAML or `yq` | New dependency; BC-03 forbids it. |
| Branch protection or a server-side hook for the push | Out of scope (PRD section 10). |
| Run the gate from a clean `git worktree add` of the commit instead of requiring a clean tree | Adds worktree metadata to the shared `.git` and a second checkout to manage; the clean-tree test proves the same equality more cheaply, and the S7b fresh clone covers the committed-content scan independently. |
| Require a PR for the push so branch protection can gate it | Contradicts BINDING-5.1 (squash-rebase, ff-merge, push, no PR). |

## Consequences

- AC-DISP has more moving parts than the PRD's script: about 60 lines instead of 30. It still needs no dependency and carries a negative self-test.
- S7 grows a clean-tree step, an out-of-tree evidence log and an independent post-push dispatch (S7b, one more devops sub-agent, about one cheap run). That is the price of making the ship control objective; the alternative is a self-reported line.
- The S7 executor needs a manifest per story and per extra round; the orchestrator must write them as it dispatches, or the ship gate fails loudly. That is the intent.
- If the PO prefers the PRD's one-file-per-stage form, the minimum change is to make the manifest describe only the final passing round of the stage and to drop the per-story requirement for `06-development`; the ADR then drops rules 4 and 5's per-story clause. Rule 5's role and length bounds remain valid either way.
