# ADR-003: Synergy Representation -- Structured Tags + Free Text Hybrid

## Status

Accepted

## Date

2026-04-01

## Deciders

Celebrimbor (Solution Architect)

## Context

The PRD (OQ-1) asks whether synergy rationale should be a free-text sentence or a structured tag system. This affects how the Optimization Reviewer counts interactions and how the user reads the deck list.

**Option A: Free text only.** Each card gets a one-sentence rationale (e.g., "Triggers Blood Artist on each sacrifice"). Human-readable but requires AI interpretation to count interactions.

**Option B: Structured tags only.** Each card gets tags (e.g., `[TRIGGERS: Blood Artist] [FEEDS: Skullclamp]`). Machine-countable but less readable for users.

**Option C: Hybrid -- structured tags + free text.** Each card gets both: tags for the Optimization Reviewer to count, and a free-text sentence for the user to understand.

## Decision

**Option C: Hybrid approach.**

The deck state includes both `synergy_tags` (structured, countable) and `synergy_rationale` (free text, readable):

```
- name: Viscera Seer
  synergy_tags: [TRIGGERS: Blood Artist] [FEEDS: Skullclamp] [ENABLES: Reassembling Skeleton]
  synergy_rationale: Free sacrifice outlet that triggers aristocrats payoffs and feeds card draw.
```

The Optimization Reviewer operates on `synergy_tags` exclusively. It counts tags, validates them against the taxonomy, and computes the synergy score. It never needs to interpret free text.

The user-facing output (per UX spec Section 3.1) shows the free-text rationale with the tag categories in parentheses:

```
Viscera Seer {B}  $0.25
  Free sacrifice outlet that triggers aristocrats payoffs and feeds card draw.
  (3 interactions: Triggers, Feeds, Enables)
```

## Consequences

**Easier:**
- Synergy counting is deterministic. The Optimization Reviewer counts tags, not interpretations.
- Users get readable explanations. The free text explains *why* a card is in the deck.
- Tag validation is straightforward. Each tag must match one of the 6 taxonomy categories and reference a card that exists in the deck.
- Debugging is clear. If the Optimization Reviewer flags a card as "isolated," you can see exactly which tags it has and which are missing.

**Harder:**
- Deck Builder must produce both formats for every non-land card. This increases output size by ~30%.
- Consistency between tags and rationale is not enforced. The free text might describe an interaction not captured in tags. Mitigated by the Rules Judge's synergy audit which cross-references oracle text.
- Tag format must be exact. The Deck Builder must use `[CATEGORY: card_name]` format precisely. Mitigated by clear format specification in `synergy-taxonomy.md` and in the agent prompt template.
