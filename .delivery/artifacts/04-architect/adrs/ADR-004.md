# ADR-004: Card Name Validation -- Exact Match with Fuzzy Fallback

## Status

Accepted

## Date

2026-04-01

## Deciders

Celebrimbor (Solution Architect)

## Context

The PRD (OQ-3) asks whether the Card Finder should use Scryfall's `/cards/search` (flexible query) or `/cards/named` (exact/fuzzy match) for card name validation.

Card name accuracy is the highest-risk failure mode (PRD PO Note #5). AI models hallucinate Magic card names -- inventing plausible-sounding but nonexistent cards. The validation function must reject hallucinated names with zero tolerance while providing helpful correction for genuine typos.

**Option A: `/cards/search?q=!"<name>"`** -- Uses the search endpoint with an exact name filter. Returns a list (possibly empty). More complex query, returns more data than needed, supports pagination.

**Option B: `/cards/named?exact=<name>`** -- Purpose-built endpoint for exact name lookup. Returns a single card or 404. Fast, simple, no pagination.

**Option C: `/cards/named?exact=<name>` with fuzzy fallback** -- Try exact match first. On 404, try `/cards/named?fuzzy=<name>` which returns Scryfall's best guess. Report the suggestion as a "did you mean?" without silently accepting it.

## Decision

**Option C: Exact match with fuzzy fallback.**

Implementation in `card_lookup.py validate`:

1. Try `/cards/named?exact=<name>`
2. If 200: card exists, return card data with `{"found": true, ...}`
3. If 404: try `/cards/named?fuzzy=<name>`
4. If fuzzy returns 200: return `{"found": false, "suggestion": "<scryfall_name>", "query": "<original_name>"}`
5. If fuzzy returns 404: return `{"found": false, "suggestion": null, "query": "<original_name>"}`

The consuming agent sees the `found: false` flag and knows the name is invalid. The `suggestion` field gives it a correction path. The agent must never silently substitute a suggestion -- it must either use the exact suggestion or report the failure.

## Consequences

**Easier:**
- Zero tolerance for hallucinated names. Exact match means "Sol Rign" does not validate.
- Typo recovery. Fuzzy fallback provides "did you mean: Sol Ring?" for genuine typos.
- Clear semantics. `found: true` = name is real. `found: false` = name is not real. No ambiguity.
- Fast. Single request for valid names (the common case). Two requests only for invalid names.

**Harder:**
- Two API calls for invalid names. Mitigated by the fact that FR-02.9 requires pre-validation during deck construction, so most names reaching the Rules Judge should already be valid.
- Fuzzy match may suggest the wrong card. "Demonic Consultancy" might fuzzy-match to "Demonic Consultation" (banned) or "Diabolic Tutor." The agent must not auto-accept suggestions -- it must validate the suggestion in context (banned list, color identity).
- Does not handle intentional abbreviations. A user saying "Sol Ring" is fine, but "SolRing" would fail exact match. The fuzzy fallback handles this case, and the agent can present the suggestion to the user during intake.
