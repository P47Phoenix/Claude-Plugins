# Theory Output Contract: inline answer

Owner: `theorist`. No artifact, no gate, no `.song/<slug>/` directory unless the user asks to save the answer. Every theory answer uses this fixed layout, in this order, as Markdown returned inline.

## Layout

```markdown
**Question:** <one sentence restating what was asked, with the key and chords given>

**Analysis**

| Bar or chord | Notes | Numeral | Function | Note |
|--------------|-------|---------|----------|------|
| D | D F# A | I | tonic | home chord |
| C | C E G | bVII | subtonic (borrowed from the key's parallel mode) | pulls away because it lacks the leading tone |

**Answer:** <2-5 sentences at the user's level; lead with the direct answer>

**Options:** (only for reharmonize, what-fits, transpose; otherwise omit)
1. <gentle option>: <chords> -- <one-line reason>
2. <medium option>: <chords> -- <one-line reason>
3. <bold option>: <chords> -- <one-line reason>

**Spelling check:** <every chord or scale named above, spelled by chord_tools.py>
Example: `Dmaj7 = D F# A C#`; `D mixolydian = D E F# G A B C`

**Source refs:** <theory and technique files used, e.g. theory/modes-scales.md, techniques/modal-color.md>
```

## Rules

1. **Order is fixed**: Question, Analysis, Answer, Options, Spelling check, Source refs. Omit Options only when the task type is not a proposal (see the theorist manifest).
2. **Analysis table** has one row per distinct chord or per bar, never prose. Columns: chord or bar, notes (spelled), Roman numeral (major-scale-relative, uppercase major, lowercase minor, `°`, `ø7`), function (tonic, predominant, dominant, borrowed, secondary dominant, passing, pedal), and a short note.
3. **Spelling check** is generated by `chord_tools.py` (`scale`, `chord`, `diatonic`, `roman`, `transpose`, `reharmonize`). No pitch name appears in the answer that the tool did not produce. Flats and sharps follow the key.
4. **Level.** Beginner: no term without a plain-word gloss, one analogy at most. Intermediate: names and functions. Advanced: voice-leading detail and a second reading of ambiguous chords. When the level is unknown, write for intermediate and offer to adjust in the last line.
5. **Source refs** names every `references/theory/` and `references/techniques/` file read; add "general practice" when the answer rests on knowledge outside those files.
6. **Length.** Whole answer under 400 words for a single question; under 600 for a multi-part one. Tables count.
7. **No song deliverable.** If the user wants chords written into a song, say so in the last line and name the harmony role; do not write `chords.md`.
8. **Originality.** Describe by function and sound, never by named songs or artists.

## Pipeline hand-back (THEORY song type)

```text
SKILL_LOADED: <comma-separated paths>
STATUS: DONE | BLOCKED
ARTIFACT: none
SUMMARY: <one sentence, max 200 characters; the direct answer>
ANSWER:
<the full layout above>
```

The orchestrator relays the text under `ANSWER:` to the user unchanged. On BLOCKED add `FINDINGS:` (for example, a chord symbol that does not parse; name it and ask for a correction).

## Worked example

**Question:** What mode is D, C, G, D, and why does C feel like it pulls away from the tonic?

| Chord | Notes | Numeral | Function | Note |
|-------|-------|---------|----------|------|
| D | D F# A | I | tonic | home |
| C | C E G | bVII | modal subtonic | whole step below the tonic, no leading tone |
| G | G B D | IV | predominant | the other modal pillar |

**Answer:** The set fits D mixolydian: a major scale with a lowered seventh. C is bVII, so it sits a whole step under D and leads back sideways instead of resolving upward by a half step.

**Spelling check:** `D mixolydian = D E F# G A B C`; `C = C E G`.

**Source refs:** theory/modes-scales.md, techniques/modal-color.md
