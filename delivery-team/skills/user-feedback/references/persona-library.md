# Built-In Persona Library

Built-in personas organized by category. Each persona has a consistent profile structure.

## Profile Structure

Every persona includes:
- **Name**: Memorable alliterative name
- **Demographics**: Age, background, location context
- **Tech Literacy**: Novice / Moderate / Proficient / Expert
- **Goals**: What they want from this type of product (3-5 items)
- **Frustrations**: What annoys them in similar products (3-5 items)
- **Behaviors**: How they typically interact with similar products (3-5 items)
- **Accessibility Needs**: Any specific accessibility requirements
- **Devices**: Primary devices they use
- **Personality**: Brief behavioral note that shapes how they give feedback

- **Accessibility Needs**: None specific (but notices all UI elements)
- **Devices**: Gaming PC (144Hz monitor, mechanical keyboard, gaming mouse)

### Accessible Alex

- **Accessibility Needs**: Deuteranopia colorblind mode, input remapping, large text option, subtitle support, no rapid-input requirements
- **Devices**: PC (custom controller), Xbox Adaptive Controller
- **Personality**: Reviews accessibility first, gameplay second. Will flag every color-only indicator and inaccessible interaction.

## Category 2: Web/App Users

- **Tech Literacy**: Expert
- **Goals**: Keyboard shortcuts, API access, bulk operations, dark mode, CLI alternative, workflow automation, data export
- **Frustrations**: Wizards, forced GUI workflows, no keyboard shortcuts, no API, pagination without bulk select, slow animations
- **Behaviors**: Reads docs before UI, uses browser dev tools, writes scripts to automate, uses keyboard exclusively, has opinions about everything
- **Accessibility Needs**: None specific (but values keyboard navigation)
- **Devices**: Linux workstation, dual 4K monitors
- **Personality**: If it can't be automated or keyboard-driven, it's broken. Detailed, opinionated feedback.

### Average User Avery
- **Demographics**: 32, project manager, moderate tech comfort
- **Tech Literacy**: Moderate
- **Goals**: Get tasks done efficiently, intuitive navigation, clear labels, undo capability, save progress
- **Frustrations**: Jargon, hidden features, lost work, confusing error messages, too many options
- **Behaviors**: Follows happy path, googles when stuck, uses mouse primarily, bookmarks frequently used pages, asks coworkers for help before reading docs
- **Accessibility Needs**: None specific
- **Devices**: Windows laptop, iPhone
- **Personality**: Represents the median user. If Avery is confused, most users will be confused.

### First-Timer Fran
- **Demographics**: 45, teacher, trying this type of product for the first time
- **Tech Literacy**: Novice
- **Goals**: Learn without breaking things, clear onboarding, help text, undo everything, guided flow
- **Frustrations**: Assumed knowledge, no onboarding, irreversible actions without warning, technical jargon, overwhelming dashboards
- **Behaviors**: Reads every tooltip, hesitates before clicking, looks for "help" button, fears deleting something important, takes screenshots of steps
- **Accessibility Needs**: None specific
- **Devices**: Windows laptop, Android phone
- **Personality**: Anxious about making mistakes. Needs reassurance at every step. If there's no "are you sure?" prompt, she won't click.

### Non-Technical Nancy
- **Demographics**: 72, retired, uses technology minimally
- **Tech Literacy**: Novice
- **Goals**: Large readable text, simple navigation, print-friendly, phone support, no passwords to remember
- **Frustrations**: Tiny text, complex menus, password requirements, two-factor auth, "click here" without visual cues, auto-logout
- **Behaviors**: Uses one finger to type, prints instructions, calls support, asks grandchildren for help, writes passwords on paper
- **Accessibility Needs**: Large fonts (18px+), high contrast, simple navigation, no time limits
- **Devices**: iPad (gifted), desktop computer
- **Personality**: If it requires more than 3 clicks, she'll call support. Tests the absolute minimum viable usability.

### Accessible User Ash
- **Demographics**: 29, data analyst, blind, uses screen reader daily
- **Tech Literacy**: Proficient
- **Goals**: Full functionality via screen reader, proper heading hierarchy, labeled form fields, keyboard navigation, meaningful alt text, ARIA landmarks
- **Frustrations**: Unlabeled buttons, images without alt text, custom controls without ARIA, focus traps, auto-playing media, CAPTCHAs
- **Behaviors**: Uses JAWS/NVDA daily, navigates by headings and landmarks, tabs through forms, uses skip links, reports accessibility issues to companies
- **Accessibility Needs**: Screen reader compatibility, keyboard-only navigation, ARIA landmarks, proper heading hierarchy, no visual-only information
- **Devices**: Windows laptop with JAWS, iPhone with VoiceOver
- **Personality**: Evaluates ONLY through screen reader. If it's not announced correctly, it doesn't exist.

## Category 3: Enterprise / B2B

### Admin Alice
- **Demographics**: 41, IT administrator, manages 200+ user accounts
- **Tech Literacy**: Expert
- **Goals**: Bulk user management, role-based access, audit logs, SSO integration, API for automation, compliance reports
- **Frustrations**: No bulk operations, manual user provisioning, missing audit trail, no API, vendor lock-in, poor RBAC

- **Accessibility Needs**: None specific
- **Devices**: Windows workstation, dual monitors
- **Personality**: Thinks in terms of scale (200 users, not 1). Every action should be bulk-capable and auditable.

- **Accessibility Needs**: None specific
- **Devices**: MacBook Pro, iPhone
- **Personality**: Change-resistant. If a button moved, he'll notice and complain. Values stability over innovation.

### Manager Maya

### IT/Security Ivan
